### 1.2 架构要点

- **三层模型**：Endpoint（IP+端口+协议+连接参数）→ Device（从站号 / 机架槽）→ Tag（结构化地址 + 数据类型 + 字节序）
- **协议驱动**：统一 `IDeviceDriver`；S7comm 走 S7NetPlus，Modbus TCP 与 RTU-over-TCP 为自研驱动（帧边界、CRC16、异常码分类）
- **采集引擎**：50ms 时间轮、每端点串行 Channel、写优先、过载跳周期、指数退避 1→30s、Good/Uncertain/Bad/Timeout 质量戳
- **写值安全**：权限 → 类型量程 → 60s 确认令牌（载荷 SHA256 绑定）→ 写入 → 回读校验 → 审计；失败逆序补偿回滚
- **历史存储**：死区 + 5 分钟快照 → `COPY ... FROM STDIN (FORMAT BINARY)` 批量入库，spool JSONL 兜底重放
- **实时推送**：WebSocket 订阅，1s 合并 + 只推变化 + 单帧 500 项分批 + 慢消费者 resync + HTTP 快照兜底
- **前端**：Vue 3 + TypeScript + Element Plus + ECharts + Pinia；组态渲染器自研（14 类图元、4 类动画）

### 2.3 关键替代说明（与原计划的差异）

| 计划书要求 | 实际采用 | 原因与等价能力 |
|---|---|---|
| TimescaleDB | **PostgreSQL 16 原生月分区 + BRIN + 聚合函数** | 环境无 Docker、无法安装扩展。用 `PARTITION BY RANGE` 按月分区、`BRIN` 索引做时间范围扫描、`sfms_ensure_partitions` / `sfms_drop_old_partitions` 做自动建/删分区、`sfms_rollup_minute` 做 1 分钟聚合，覆盖 hypertable 的核心能力（时间分区、自动保留、连续聚合）。若环境已装 TimescaleDB，可执行 `tools/db/sql/090_timescale_optional.sql` 升级为 hypertable。 |
| Docker Compose 编排 | **便携 PostgreSQL + 一键 PowerShell 脚本** | 目标机器无 Docker。`tools/start-all.ps1` 按序拉起 PG → 模拟器 → API 并做就绪探测，`stop-all.ps1` 按命令行模式停止，效果等价于 compose up/down。 |
| 商业 SCADA 组态（如 WinCC/组态王） | **自研轻量组态（Vue3 + 内联 SVG）** | 免授权、可二次开发、与业务系统同源。14 类图元 + 4 类动画（stateMap / linear / needle / blink / quality）+ 8px 吸附 + 撤销重做 100 步 + 版本发布回滚。 |
| Redis 实时域 | **进程内 `IRealtimeStore` 实现**（Redis 实现接口已预留） | 单实例部署下性能足够（10 万次/秒级内存读写）；横向扩展时替换实现即可，业务代码零改动。 |

### 2.4 自研部分（无第三方依赖）

- Modbus TCP / RTU-over-TCP 驱动（帧边界、CRC16、功能码与异常码映射、跨寄存器对齐）
- 地址解析器（S7 `DB1.DBW0` / `M10.0` / `I0.5` / `Q2.1` / `VW100`，Modbus `HR:0` / `IR:10` / `C:0` / `DI:7` 与四万六万式）
- 值编解码（四种字节序 ABCD/CDAB/BADC/DCBA 与全类型换算）
- 50ms 时间轮采集调度、写值六步安全流程、报警引擎、WebSocket 推送协议
- 双协议模拟器（Modbus 从站 1~6、S7 数据块、故障注入代理、控制面）

## 四、快速开始

```powershell
# 1) 准备便携数据库（幂等，只需执行一次）
powershell -ExecutionPolicy Bypass -File tools/db/setup-pg.ps1

# 2) 一键启动：PostgreSQL → 双协议模拟器 → API
powershell -ExecutionPolicy Bypass -File tools/start-all.ps1

# 3) 浏览器打开（前端产物由 API 直接托管）
start http://127.0.0.1:5080
#    admin / admin123   engineer / eng123   operator / op1234   observer / ob1234

# 4) 可选：验证
tools/sim/.venv/Scripts/python.exe tools/verify_e2e.py   # 62 项端到端
tools/sim/.venv/Scripts/python.exe tools/verify_ui.py    # 17 个页面

# 5) 停止
powershell -ExecutionPolicy Bypass -File tools/stop-all.ps1
```

端口占用：API `5080`、PostgreSQL `5433`、Modbus TCP `1502`、Modbus RTU-over-TCP `1503`、S7 `1103`、故障代理 `1102` / `1504`、模拟器控制面 `18080`。

## 五、已知限制

1. **无真实 PLC 环境**：协议正确性通过自研模拟器 + 第三方客户端（pymodbus / python-snap7）交叉验证；现场接入前建议用真实设备再跑一次端点"测试"与点位"在线调试"。
2. **Modbus RTU 经串口服务器（RTU over TCP）**，不直接接管本机 COM 口；串口直连需补 `System.IO.Ports` 适配层。
3. **S7-200 经典型号**不支持 S7comm，需经 S7-200 SMART 或串口服务器转换，界面会给出提示。
4. **Redis** 当前用进程内实现（单实例足够），多实例横向扩展时替换 `IRealtimeStore` 为 Redis 实现即可。
5. **历史表**用 PostgreSQL 原生分区等价替代 TimescaleDB，见 2.3。
