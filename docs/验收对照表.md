## 非功能条目

| 条目 | 目标 | 实现 | 状态 |
|---|---|---|---|
| 采集周期下限 | 200 ms | 分组周期校验 200~60000 且 50 倍数；时间轮 50 ms | 已实现 |
| 时序数据规模 | 万点级、月分区 | PostgreSQL 原生 `PARTITION BY RANGE` + BRIN + `COPY BINARY` 批量写 + 1 分钟聚合表 | 已实现 |
| 断线续传 | 不丢历史 | `HistoryWriter` 有界 Channel + `spool/history-*.jsonl` 落盘重放 | 已实现 |
| 写入安全 | 防误操作/防重放 | 60 秒确认令牌 + 载荷 SHA256 绑定 + 回读校验 + 补偿回滚 + 审计 | 已实现 |
| 推送效率 | 只推变化 | delta 帧按变化点推送，单帧 500 项分批，慢消费者 resync | 已实现 |
| 组态可用性 | 工控友好 | 14 类图元、stateMap/linear/blink/quality 四类动画、8px 吸附、撤销重做 100 步 | 已实现 |
| 部署方式 | 免安装、可离线 | 便携 PostgreSQL + .NET SDK 自包含运行 + 一键脚本 | 已实现 |

## 当前限制（如实说明）

1. **无真实 PLC 环境**：协议正确性通过自研双协议模拟器 + 第三方客户端（pymodbus / python-snap7）交叉验证，
   现场接入前建议用真实设备再跑一次端点"测试"与点位"在线调试"。
2. **Modbus RTU 走串口服务器（RTU over TCP）**：不直接接管本机 COM 口；如需串口直连，需增加 `System.IO.Ports` 适配层。
3. **S7-200 经典型号**：S7comm 不支持，需经 S7-200 SMART 或串口服务器转换；界面会给出提示。
4. **Redis**：当前用进程内缓存实现实时域（单实例部署足够）；多实例横向扩展时替换 `IRealtimeStore` 为 Redis 实现即可。
5. **历史表**用 PostgreSQL 原生分区等价替代 TimescaleDB；若环境已装 TimescaleDB，可执行 `tools/db/sql/090_timescale_optional.sql` 升级为 hypertable。
