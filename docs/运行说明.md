# SFMS 运行说明

厂区设备检测系统（Shop-floor Facility Monitoring System）。本文覆盖：环境准备、首次部署、日常启动、
端口与账号、功能入口、故障排查。

---

## 1. 技术栈与端口

| 组件 | 技术 | 端口 | 说明 |
|---|---|---|---|
| 采集与 API | .NET 8（ASP.NET Core + 后台采集服务） | 5080 | 同时托管已构建的前端 |
| 前端开发服务器 | Vue 3 + Vite 5 | 5173 | 仅在 `-Dev` 模式下使用 |
| 数据库 | PostgreSQL 16（便携实例，免安装） | 5433 | 避免与本机已装 PostgreSQL 冲突 |
| Modbus TCP 从站 | Python 自研模拟器 | 1502 | 6 台电表 + 2 台产线设备 |
| Modbus RTU over TCP | 同上 | 1503 | 2 台 RTU 电表 |
| S7 服务端 | python-snap7（纯 Python） | 1103 | DB1/DB2/DB3/DB10 + M/I/Q |
| 故障注入代理 | Python | 1102 / 1504 | 1102→1103、1504→1502，可注入延时/丢包/断链 |
| 模拟器控制面 | Python HTTP | 18080 | 故障注入与状态查询 |

> 选 1502/1503/1102/1103 而不是 502/102 是为了在非管理员权限下运行，同时仍能验证协议栈。

## 2. 环境准备（一次性）

需要：**Windows 10/11**、**.NET 8 SDK**、**Node.js 18+**、**Python 3.11+**。

```powershell
# 2.1 检查 .NET SDK（应看到 8.0.x）
dotnet --list-sdks

# 2.2 前端依赖
cd web; npm install; cd ..

# 2.3 模拟器依赖（虚拟环境 + 两个库）
python -m venv tools\sim\.venv
tools\sim\.venv\Scripts\pip install -r tools\sim\requirements.txt

# 2.4 便携 PostgreSQL：解压 → initdb → 建库（幂等，可重复执行）
.\tools\db\setup-pg.ps1
```

`setup-pg.ps1` 完成后会打印连接串：
`Host=127.0.0.1;Port=5433;Database=sfms;Username=postgres;Password=postgres`

## 3. 启动

```powershell
# 仅后端（前端已构建到 src/SFMS.Api/wwwroot，由 API 直接托管）
.\tools\start-all.ps1

# 开发模式：额外起 Vite（5173，热更新，/api 与 /ws 由 Vite 代理到 5080）
.\tools\start-all.ps1 -Dev

# 对接真实 PLC（不启动模拟器）
.\tools\start-all.ps1 -SkipSim

# 先构建再启动
.\tools\start-all.ps1 -Build
```

打开 <http://127.0.0.1:5080>（或开发模式 <http://127.0.0.1:5173>）。

停止：

```powershell
.\tools\stop-all.ps1            # 停 API + 模拟器 + 数据库
.\tools\stop-all.ps1 -KeepDb    # 保留数据库实例
```

## 6. 模拟器控制（验证用）

```powershell
# 当前状态（寄存器、S7 数据块、故障列表）
curl http://127.0.0.1:18080/state

# 给 Modbus 从站 1 注入 3 次"服务忙"异常（触发 Bad 质量与通信报警）
curl -X POST http://127.0.0.1:18080/fault -H "Content-Type: application/json" `
     -d '{"target":"modbus","unit":1,"kind":"exception","count":3}'

# 给 S7 注入 2 秒延时
curl -X POST http://127.0.0.1:18080/fault -H "Content-Type: application/json" `
     -d '{"target":"s7","kind":"delay","ms":2000,"count":1}'

# 一键清除
curl -X POST http://127.0.0.1:18080/fault/clear
```

协议自检（用第三方客户端交叉验证，避免"自己测自己"）：

```powershell
tools\sim\.venv\Scripts\python.exe tools\sim\verify_protocols.py
```

## 7. 故障排查

| 现象 | 原因与处理 |
|---|---|
| API 起不来，日志报 `42P01 relation "tags" does not exist` | 数据库未初始化。确认 `setup-pg.ps1` 执行过，且连接串端口为 5433 |
| 点位质量长期 `Bad`，诊断页 `lastError` 含 `PUT/GET` | S7 侧需勾选「允许来自远程对象的 PUT/GET 通信访问」，并取消数据块「优化的块访问」 |
| Modbus 读回全 0 或数量级不对 | 32 位点位字节序不对。用诊断页「点位在线调试」比对 ABCD/CDAB/BADC/DCBA 四值 |
| 画面不刷新，右上角显示"已断开" | WebSocket 票据过期或代理未转发 `/ws`。开发模式下确认 Vite 代理 `ws: true` |
| 写入被拒 `写入需要操作员及以上权限` | 当前账号是观察员，换 `operator` 及以上 |
| 写入预览出现 `量程超限` | 目标值超出点位配置的 Min/Max，先改量程或改值 |
| 采集过载报警频繁 | 扫描周期过短或单帧点位过多。调大分组周期或增点合并间隔（`mergeGap`） |
| 端口被占用 | `start-all.ps1 -ApiPort 5081 -PgPort 5434`，同时改 `web/vite.config.ts` 代理端口 |

日志位置：`.run\api.out.log`、`.run\api.err.log`、`.run\sim.out.log`、`.run\pg.log`。

## 8. 数据与备份

- 运行时数据：`.pgdata/`（PostgreSQL 数据目录），备份用 `pg_dump`。
- 历史表按**月分区**（`tag_history` / `tag_agg_1m` / `audit_log` / `endpoint_diag_minute`），
  后台每小时自动建未来 3 个月分区，每天清理 3 个月前的历史与 12 个月前的审计。
- 手工维护：管理员在「通信诊断」页点"时序维护"，或 `POST /api/diagnostics/maintenance`。
- 若使用 TimescaleDB：执行 `tools/db/sql/090_timescale_optional.sql`（仅空库首次初始化）。
